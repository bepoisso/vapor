# CLAUDE.md — Vapor

## What this repo is
Vapor: an open-source desktop client for Steam (library browsing + game launching). Start with the **Library page**. The full context lives in `docs/` — read `docs/CONTEXT.md` before writing code.

## Source of truth
- **Visual target:** `mockups/library.html`. Match its layout, spacing, colors, type and hover behavior. When the mockup and the docs disagree, the mockup wins on visuals and `docs/LIBRARY_SPEC.md` wins on behavior.
- **Tokens:** `docs/DESIGN_SYSTEM.md`. Never hard-code a color, radius or font size in a component; use the tokens.
- **Data model:** `mockups/data/games.sample.json` shows the shape the UI consumes. The real data layer must produce the same shape (see `docs/STEAM_INTEGRATION.md`).

## Stack (confirmed by the owner, see `docs/DECISIONS.md`)
- **Tauri 2** (Rust backend) + **React 19** (with React Compiler) + **TypeScript** (strict) + **Vite**. Package manager: **pnpm**.
- Styling: CSS variables from `DESIGN_SYSTEM.md` (`src/styles/tokens.css`) + CSS Modules. No component library, no Tailwind.
- Routing: TanStack Router (hash history). State: React state + Zustand for library data and filters. Long grids: TanStack Virtual.
- UI language: **English only**. Strings live in `src/i18n/locales/en.json` (react-i18next, typed keys), never inline in components.
- Rust ↔ TS: commands are annotated with `#[specta::specta]`; **tauri-specta** generates `src/lib/bindings.ts` (committed, never edited by hand; regenerated by `cargo test` and by debug runs, CI fails if stale).
- Rust side owns everything that touches the file system, Steam files, the network and process launching. The frontend talks to it via Tauri commands only.
- Target platform first: **Windows** (owner's machine). Keep paths abstracted so Linux/macOS can follow.

## Commands
- `pnpm tauri dev` run the app · `pnpm test` · `pnpm lint` · `pnpm typecheck` · `pnpm format`
- In `src-tauri/`: `cargo test` · `cargo clippy --all-targets -- -D warnings` · `cargo fmt`
- `VAPOR_LIBRARY=sample pnpm tauri dev`: run on the mockup's sample library instead of the local Steam install. Vapor's cache (library snapshot, thumbnails) lives in the OS cache dir under `io.github.bepoisso.vapor`.
- In `src-tauri/`: `cargo test real_install -- --ignored --nocapture` prints what a scan of this machine's Steam install finds.
- `pnpm compare:mockup`: screenshots the real app next to `mockups/library.html` (same engine, 1440 px) into `artifacts/compare/`.
- `pnpm perf:library [games] [--release]`: scroll smoothness and interaction latency with a synthetic library. `pnpm perf:startup`: startup stages of the release build. Build the release first with `pnpm tauri build --no-bundle`.

## Performance budgets (checked at the end of every phase)
- Window visible with the library rendered: **< 300 ms** from Vapor's cache.
- Scroll: **60 fps** with 2,000 games. Interactions (chips, pills, search): **< 16 ms**.
- RAM **< 150 MB**, installer **< 15 MB**.
- The window starts hidden with the `--bg` color and is revealed after the first paint (`src/lib/window.ts`). Animate only `transform`/`opacity`. Serve resized thumbnails, not full-size art, to grids.

## Conventions
- English everywhere: code, comments, commits, docs and the app UI. UI strings go through the i18n layer (`en` only).
- TypeScript `strict`. No `any` without a comment explaining why.
- Small components, one per file. Feature folders: `src/features/library/…`.
- Rust: `clippy` clean, errors via `thiserror`, no `unwrap()` on user data or file I/O.
- Accessibility: real `<button>`/`<a>`, visible focus ring (accent color), `aria-pressed` on toggle chips, alt text on logos.
- Performance matters (the whole point is "faster than Steam"): virtualize long grids, lazy-load images, keep first paint under ~300 ms on cached data.

## Don'ts
- Don't commit anything from `mockups/assets/` or any copyrighted game art to a public remote. Suggested `.gitignore` line: `mockups/assets/`.
- Don't scrape Steam pages or use undocumented endpoints without flagging it to the owner.
- Don't store the user's Steam password. Ever. See `docs/STEAM_INTEGRATION.md` for auth.
- Don't invent stats in the UI: if a value is unknown, show nothing or a neutral placeholder.

## Workflow
